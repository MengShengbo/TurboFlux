# 本地插件生命周期

最后更新：2026-09-15。Desktop 只管理本地安装与随应用提供的插件；不再提供官方市场、远端目录、下载队列或自动更新。

## 安装与运行

1. 设置中的“本地插件”通过系统目录选择器选择插件目录。
2. `DesktopRuntimeHost` 检查 manifest、代码入口和权限，取得明确权限选择后，将检查过的路径交给 `PluginService` 安装。
3. `PluginService` 负责安装记录、启停、贡献项注册和卸载。代码插件仍使用独立子进程和现有权限边界。
4. `workPackCatalog.ts` 只投影已经安装的 Skills 与 Plugins；插件投影出来的 Skill 不重复列为独立插件。
5. 详情页显示真实来源、作者、版本、许可、能力和权限。多能力插件可以逐项挂载；停用状态无法挂载。

本地重新安装是显式操作。没有定期联网刷新、远端升级或从市场条目安装的入口。

## 内置插件与旧记录

`bundledPlugins.ts` 保存随应用提供的 Office 和 Design Atlas。Office 默认启用，Design Atlas 默认停用。已有本地同 ID 插件不会被内置包替换。

旧市场安装记录读入后归为本地来源，保留插件文件和启停状态。旧远端目录及下载任务不再参与启动或恢复。移除市场不能误删用户已安装的插件。

## 验证范围

- Core 测试覆盖本地安装与启停、权限、贡献项、内置包和旧记录保留。
- Desktop 契约测试覆盖目录选择、检查、权限审批、安装路径以及窄 IPC 接口。
- 实际 Renderer 的浏览器 fixture 覆盖搜索、详情、启停、逐项挂载、卸载回调、错误与忙碌状态，并检查深浅主题和宽窄布局。
- 浏览器 fixture 不替代原生文件选择器或真实插件进程的 Electron 验收。
