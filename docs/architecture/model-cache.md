# 模型请求与缓存诊断边界

模型前缀缓存由上游执行。内核负责保持可复用的请求前缀、发送一致的缓存路由键，并准确记录输入用量与请求变化；缓存键相同不代表上游一定命中。

| 层 | 职责 |
| --- | --- |
| AgentEngine / 协议适配 | 准备消息与工具、发送请求、处理兼容性重试，保留最后一次实际发送的序列化请求体 |
| modelRequestCache | 从实际请求体提取统一的缓存快照；没有有效输入用量时不更新基线 |
| CacheMonitor | 比较相邻已观测请求的系统内容、工具、消息前缀、控制参数及缓存读取量 |
| 上游路由与模型服务 | 选择缓存实例、保存与淘汰前缀、返回缓存命中用量 |

## 请求事实

`modelRequestCache.ts` 为 Responses、Chat Completions、Anthropic Messages 提供同一个观测入口。它使用最终发送的 `serializedBody`，因此被兼容性重试删除或降级的参数不会继续进入缓存基线。Anthropic 的强制工具选择、thinking、cache_control，以及 Chat 的 reasoning_effort 均来自实际请求。

只在响应有有效输入 token 用量后更新基线。无用量响应和中途被拒绝的请求不能覆盖上一条已测量请求。身份凭据和每次变化的追踪请求头不进入快照；协议版本与 Anthropic beta 标识可参与参数比较。预发送的模块预览和最终响应诊断具有不同语义。

协议适配层同时提供最后一次实际发送时间和响应结束时间。诊断中的空闲间隔为本次发送时间减去上次响应结束时间，不把本次推理或生成时间计入缓存查找之前的等待。诊断保留 `requestTiming.idleMs` 与 `durationMs` 供核对。TTL 仍只是启发式提示，客户端不知道上游缓存写入、路由与淘汰的确切时点，不能仅凭请求耗时确认缓存过期。

快照只供本地比较，不负责路由、重试或执行工具。缓存下降是观测结果；若本地前缀没有改变，也不能进一步断言具体是缓存淘汰、后端路由或上游统计错误。

## 上下文与路由

- 同工作区相同模型、模式和工具集合使用稳定缓存键；会话内容仍由真实消息决定。
- 新用户输入不自动删除上一轮工具证据。只有明确压缩、上下文预算和视觉预算可以替换已发送上下文。
- Responses 正常请求保持稳定的工具选择与并行参数。模式声明仍在任何工具执行前校验，违约时最多执行一次明确记录的强制声明重试。
- 总体命中率使用 `Σcached / Σinput`，输入已包含缓存部分。冷启动、首次读入的新内容和服务端未命中均保留在总体统计中。协议回放实验与真实任务统计分别报告。

## 验证边界

`modelRequestCache.test.ts` 覆盖三种协议、参数保真、凭据排除、无用量不污染基线和 Responses 工具项识别。`agentEngine.test.ts` 验证真实重试路径：请求被拒绝后删除一个参数，再收到缓存下降时，诊断必须指出实际参数变化。相同请求体与请求头的独立 HTTP 回放用于区分客户端改写和上游缓存状态，不能用于替代任务验收。


## 请求账本与历史用量

`ModelRequestRecord` 由 contracts 定义。`requestId` 标识一次逻辑模型调用，`id` 标识一次实际尝试；同一调用因400兼容性回退或网络重试产生不同尝试。记录只保留请求指纹、模型/协议、时间、状态、上游响应ID及数值用量，不保存认证信息或原始请求正文。

主模型流式请求和上下文压缩的非流式请求通过 ModelRequestTracker 发布 `model:request`。用量字段沿用 provider 的累计语义，单次尝试后续报告覆盖同一记录；无报告时保持 `source: unknown`。输出中已经包含的推理token单独展示，不再次加到总用量。缓存字段缺失时保持缺失，汇总缓存率只使用同时有input/cached的样本，并公开对应输入基数。

conversations 将其转换为 `model.request_updated` 并持久化到V2事件与快照。历史回放恢复记录及已知usage，重复事件与重复最终快照不重复计数。消息重写不抹去已发生的用量；启动后仍是running的历史请求展示为interrupted且final=false，不推断未返回的消耗。已有旧日志可继续读取，没有原始用量的旧记录不会补造为零。

工作台 `context.modelUsage` 暴露已知合计、未知/不完整尝试数、逻辑请求数及加权缓存率；个人活动按attemptId去重，从而同一模型步骤中的两个实际尝试不会相互覆盖。新事件需要新版读取器，尚未替换的旧安装版不能作为新日志读取兼容性验证。

当前子Agent仍走独立的进度统计通道；它们尚未纳入这套逐尝试账本，报告不能宣称覆盖了全部子任务。标准验证入口见 `scripts/kernel-benchmark/README.md`。
