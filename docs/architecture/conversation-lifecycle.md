# 会话事件与界面状态

任务生命周期由 `WorkbenchRuntime.runPrompt` 统一收尾。模型停止输出、单次模型调用结束和整个任务完成是不同的事实：工具调用、补充输入或重试仍可能在一次模型输出后继续发生。

## 发布顺序与职责

1. `run.started` 建立任务，再依次发布输入、模型步骤、流式内容和工具事件。
2. `stream.ended` 只关闭一个输出通道；`turn.completed` 提交这一条消息。
3. `execution.updated` 提供执行中的任务、计划、活动与计时分段。
4. AgentEngine 完成任务核算并返回后，拥有运行 Promise 的 WorkbenchRuntime 发布唯一的 `run.completed`。它携带真实 outcome、完整 WorkRun、结束时间、执行分段和最终 AgentRunState。
5. `settlePromptRun` 释放运行所有权、处理下一条排队输入，再发布完整工作台快照。不会在完成事件后发布同一任务仍在 running 的过渡快照。

`session:complete` 和 `error` 是引擎内部通知，不再单独推断规范任务的成功或失败。终态 WorkRun 通过 `run.completed` 一次提交，不再从另一个执行快照通道提前提交。上下文准备在每次模型调用之前执行；最终答复后不再等待额外的上下文压缩请求。

## 消费与回放

`@turboflux/presentation` 的 `conversationViewProjection` 同时推进任务流、执行时间和运行状态。桌面端在同一帧渲染其结果，不补算任务是否完成。事件以 conversationId、generation 和 seq 定位：

- 重复事件和较旧快照不能覆盖已呈现的状态。
- 缺少序号时暂停应用后续事件，读取完整快照后继续，避免完成信号越过尚未收到的内容。
- 历史重写递增 generation，因此新历史可以从较小序号开始；旧历史迟到的事件不能污染新历史。
- 完成后的任务只能由新的 `run.started` 重新进入执行状态。

`@turboflux/conversations` 的 V2 持久化直接从完成事件保存任务结果和计时分段，同时保留旧日志的读取兼容。消息内容节点按内容增量更新，页面切换动画不由后台状态刷新重新触发。

## 验证边界

回归覆盖成功、部分完成、失败、取消、暂停计时、事件缺口、重复事件、旧快照、历史重写代次及日志回放。桌面验收使用独立用户目录，不修改日常使用中的会话；通过注入规范事件，检查完成事件到用时显示的延迟、消息节点是否保留，以及首页是否重复播放入场动画。
